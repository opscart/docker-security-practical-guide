## 🔴 The Production Problem

**Scenario:** A compromised container registry allowed attackers to replace legitimate images with malicious versions.

**The Attack Timeline:**

1. **Initial Compromise:** Attacker gained access to container registry credentials (leaked in GitHub)
2. **Image Replacement:** Replaced production `backend-api:v2.3.1` image with identical tag containing backdoor
3. **Deployment:** CI/CD pipeline pulled and deployed the malicious image (tag matched, no signature verification)
4. **Data Exfiltration:** Backdoor exfiltrated customer PII to attacker-controlled server for 6 days
5. **Discovery:** Security team detected unusual outbound traffic patterns

**Impact:**

- **47,000 customer records** exfiltrated (names, emails, order history)
- **$2.3M GDPR fine** for data breach
- **8 days downtime** during incident response and forensic analysis
- **$850K** in legal fees and breach notification costs
- **Permanent reputation damage** and customer trust erosion

**Root Cause:**

1. ✅ **No image signing** - Anyone with registry access could push images
2. ✅ **Tag-based deployment** - CI/CD trusted tags, not cryptographic signatures
3. ✅ **Registry credentials leaked** - Found in public GitHub repo
4. ✅ **No admission control** - Kubernetes didn't verify signatures before running containers
5. ✅ **No runtime integrity checks** - No detection that running image ≠ expected image

**What Should Have Been Done:**

- ❌ No signing → ✅ **Sign all images with Cosign**
- ❌ Tag-based trust → ✅ **Verify signatures before deployment**
- ❌ No admission control → ✅ **Kubernetes policy: only signed images can run**
- ❌ Leaked credentials → ✅ **Cosign keyless signing (OIDC-based)**
- ❌ No integrity checks → ✅ **Runtime verification with Falco/Sigstore Policy Controller**

**Result with signing:** Even if registry compromised, **unsigned images cannot be deployed** (admission controller blocks), **tampered images detected** (signature mismatch), **attack surface reduced** to key theft (far harder than credential leak).

## 📖 Detailed Walkthrough

### Part 1: Understanding Image Signing

**Why Sign Container Images?**

Container images can be tampered with at multiple points:

```
Developer → Build → Registry → Deployment
    ↓         ↓         ↓           ↓
  Insider  Compromised  MITM     Malicious
  Threat    Build       Attack    Replica
```

**Without signing:**
- ✅ Attacker replaces `myapp:v1.0` with malicious version
- ✅ CI/CD pulls and deploys it (tag matches!)
- ✅ No way to detect tampering

**With signing:**
- ❌ Attacker replaces image but **cannot forge signature**
- ❌ Deployment **fails signature verification**
- ✅ Tampered image **blocked at admission control**

**How Signing Works:**

```
1. Developer builds image
2. Developer signs image digest with PRIVATE key
   → Creates signature (detached, stored in registry)
3. Signature uploaded to registry alongside image
4. At deployment:
   - Pull image
   - Pull signature
   - Verify signature with PUBLIC key
   - If valid → deploy
   - If invalid → BLOCK
```

**Cosign vs. Docker Content Trust:**

| Feature | Cosign | Docker Content Trust (Notary) |
|---------|--------|-------------------------------|
| **Backing Project** | Sigstore (CNCF) | Docker Inc. |
| **Keyless Signing** | ✅ Yes (OIDC) | ❌ No |
| **OCI Support** | ✅ Yes | ⚠️ Limited |
| **Kubernetes Integration** | ✅ Policy Controller | ❌ Manual |
| **SBOM Attestation** | ✅ Yes | ❌ No |
| **Adoption** | Growing rapidly | Declining |

**Verdict:** Use **Cosign** for new projects.

### Part 2: Setting Up Cosign

**Step 1: Install Cosign**

```bash
# macOS
brew install cosign

# Linux
wget https://github.com/sigstore/cosign/releases/latest/download/cosign-linux-amd64
chmod +x cosign-linux-amd64
sudo mv cosign-linux-amd64 /usr/local/bin/cosign

# Verify installation
cosign version
```

**Step 2: Run Setup Script**

```bash
./setup-signing.sh
```

**What the script does:**

```bash
# 1. Verify Cosign installation
cosign version

# 2. Generate key pair
cosign generate-key-pair
# Creates: cosign.key (private), cosign.pub (public)

# 3. Start local Docker registry
docker run -d -p 5001:5000 --restart=always --name registry registry:2
```

**Expected output:**

```
Setting up image signing with Cosign...
✓ Cosign: v2.x.x

Generating key pair (enter a password)...
Enter password for private key: ********
Enter password for private key again: ********
Private key written to cosign.key
Public key written to cosign.pub
✓ Keys generated

Starting registry on port 5001...
✓ Registry on localhost:5001

✅ Setup complete!
```

**Important: Save Your Password!**

The password encrypts `cosign.key`. **If you lose it, you cannot sign images.**

**Inspect Generated Keys:**

```bash
# View public key (safe to share)
cat cosign.pub
```

**Expected output:**

```
-----BEGIN PUBLIC KEY-----
MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE...
-----END PUBLIC KEY-----
```

```bash
# View private key (encrypted, NEVER share)
cat cosign.key
```

**Expected output:**

```
-----BEGIN ENCRYPTED COSIGN PRIVATE KEY-----
eyJrZGYiOnsibmFtZSI6InNjcnlwdCIsInBhcmFtcyI...
-----END ENCRYPTED COSIGN PRIVATE KEY-----
```

**Key Storage Best Practices:**

- 🔒 **Private key (`cosign.key`)**: Store in secrets manager (HashiCorp Vault, AWS Secrets Manager)
- 🌐 **Public key (`cosign.pub`)**: Distribute widely (embed in Kubernetes ConfigMap, publish to keybase)
- 🔑 **Password**: Store separately from key (password manager, HSM)

**Production Alternative: Keyless Signing**

Cosign supports **keyless signing** using OIDC providers (GitHub, Google, Microsoft):

```bash
# Sign with GitHub OIDC (no keys needed!)
cosign sign myregistry/myapp:v1.0

# Verification uses certificate transparency log
cosign verify myregistry/myapp:v1.0 --certificate-identity=user@example.com
```

This lab uses **key-based signing** for simplicity.

### Part 3: Signing Container Images

**Step 1: Build and Sign**

```bash
./sign-image.sh
```

**What the script does:**

```bash
# 1. Create simple Alpine-based image
cat > Dockerfile << 'DF'
FROM alpine:3.20.3
CMD ["echo", "Signed Image"]
DF

# 2. Build image
docker build -t localhost:5001/signed-app:v1.0 .

# 3. Push to local registry
docker push localhost:5001/signed-app:v1.0

# 4. Sign the image
cosign sign --key cosign.key localhost:5001/signed-app:v1.0
```

**Expected output:**

```
Building and signing image...
[+] Building 2.1s (5/5) FINISHED
Successfully tagged localhost:5001/signed-app:v1.0

The push refers to repository [localhost:5001/signed-app]
v1.0: digest: sha256:abc123... size: 528

Signing image (enter your key password)...
Enter password for private key: ********

Pushing signature to: localhost:5001/signed-app
✅ Image signed!
```

**What Just Happened?**

1. ✅ Image built with digest `sha256:abc123...`
2. ✅ Image pushed to registry
3. ✅ Cosign created signature for **digest** (not tag!)
4. ✅ Signature pushed to registry as separate artifact

**Inspect Signature:**

```bash
# View signature metadata
cosign tree localhost:5001/signed-app:v1.0
```

**Expected output:**

```
📦 IMAGE INDEX for localhost:5001/signed-app:v1.0
└── 💾 sha256:abc123... (linux/amd64)
    └── 🔐 sha256:def456... (signature)
```

**Download and inspect signature:**

```bash
cosign download signature localhost:5001/signed-app:v1.0 | jq .
```

**Expected output:**

```json
{
  "critical": {
    "identity": {
      "docker-reference": "localhost:5001/signed-app"
    },
    "image": {
      "docker-manifest-digest": "sha256:abc123..."
    },
    "type": "cosign container image signature"
  },
  "optional": {
    "Bundle": {
      "SignedEntryTimestamp": "...",
      "Payload": {
        "body": "...",
        "integratedTime": 1712345678,
        "logIndex": 12345
      }
    }
  }
}
```

**Key Points:**

- ✅ Signature binds to **image digest**, not tag
- ✅ Signature stored separately in registry
- ✅ Signature includes timestamp (Rekor transparency log)

**Step 1: Verify Signed Image**

```bash
./verify-image.sh
```

**What the script does:**

```bash
cosign verify --key cosign.pub localhost:5001/signed-app:v1.0
```

**Expected output (SUCCESS):**

```
Verification for localhost:5001/signed-app:v1.0 --
The following checks were performed on each of these signatures:
  - The cosign claims were validated
  - The signatures were verified against the specified public key

[
  {
    "critical": {
      "identity": {
        "docker-reference": "localhost:5001/signed-app"
      },
      "image": {
        "docker-manifest-digest": "sha256:abc123..."
      },
      "type": "cosign container image signature"
    },
    "optional": {
      "Bundle": {
        "SignedEntryTimestamp": "...",
        "Payload": {
          "integratedTime": 1712345678,
          "logIndex": 12345
        }
      }
    }
  }
]

✅ Signature VALID
```

**What Cosign Verified:**

1. ✅ Signature exists for this image digest
2. ✅ Signature was created with the private key matching `cosign.pub`
3. ✅ Image digest has not been modified since signing
4. ✅ Signature was recorded in Rekor transparency log

**Step 2: Test Tampered Image Detection**

Let's modify the image and see if verification fails:

```bash
# Pull the signed image
docker pull localhost:5001/signed-app:v1.0

# Modify it (add a file)
docker run --name temp localhost:5001/signed-app:v1.0
docker exec temp touch /malware.sh
docker commit temp localhost:5001/signed-app:v1.0-tampered
docker push localhost:5001/signed-app:v1.0-tampered

# Try to verify tampered image
cosign verify --key cosign.pub localhost:5001/signed-app:v1.0-tampered
```

**Expected output (FAILURE):**

```
Error: no matching signatures:
failed to verify signature

✗ Signature INVALID
```

**Why verification failed:**

- Image digest changed (new layer added)
- Signature still points to original digest
- Mismatch detected → **BLOCKED**

**Test 1: Signed Image (Should Succeed)**

**Output:**

```

✅ Signature VALID

v1.0: Pulling from signed-app

```

**Test 2: Unsigned Image (Should Fail Verification)**

```bash
# Build unsigned image
docker build -t localhost:5001/unsigned-app:v1.0 .
docker push localhost:5001/unsigned-app:v1.0

# Try to verify (no signature exists)
cosign verify --key cosign.pub localhost:5001/unsigned-app:v1.0
```

**Output:**

```
Error: no matching signatures:
failed to verify signature

Verification failed (expected - image not signed)
```

**Test 3: Kubernetes Admission Policy**

The script generates a Kubernetes **ClusterImagePolicy** that enforces signature verification:

```yaml
apiVersion: policy.sigstore.dev/v1beta1
kind: ClusterImagePolicy
metadata:
  name: signed-images-policy
spec:
  images:
  - glob: "**"  # Apply to ALL images
  authorities:
  - key:
      data: |
        -----BEGIN PUBLIC KEY-----
        MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE...
        -----END PUBLIC KEY-----
```

**How it works:**

1. ✅ Kubernetes **Admission Controller** intercepts pod creation
2. ✅ Checks if image has valid signature (using public key)
3. ✅ **Allows** signed images
4. ❌ **BLOCKS** unsigned images

**Deploy admission policy (requires Sigstore Policy Controller):**

```bash
# Install Sigstore Policy Controller
kubectl apply -f https://github.com/sigstore/policy-controller/releases/latest/download/release.yaml

# Apply policy
kubectl apply -f admission-policy.yaml

# Test: Deploy signed image (should succeed)
kubectl run signed-test --image=localhost:5001/signed-app:v1.0

# Test: Deploy unsigned image (should be BLOCKED)
kubectl run unsigned-test --image=localhost:5001/unsigned-app:v1.0
# Error: admission webhook "policy.sigstore.dev" denied the request:
# validation failed: failed to verify signature
```

## 🔒 Production Security Checklist

### Key Management
- [ ] Generate strong key pairs (`cosign generate-key-pair`)
- [ ] Store private key in secrets manager (Vault, AWS Secrets Manager)
- [ ] Distribute public key widely (ConfigMap, documentation)
- [ ] Rotate keys every 90 days
- [ ] Use keyless signing (OIDC) for ephemeral workloads

### Signing Process
- [ ] Sign ALL images before deployment
- [ ] Sign by digest, not tag (`image@sha256:...`)
- [ ] Include SBOM attestations (`cosign attest --type spdxjson`)
- [ ] Record signatures in transparency log (Rekor)
- [ ] Automate signing in CI/CD pipeline

### Verification
- [ ] Verify signatures before deployment
- [ ] Use Kubernetes admission controller (Policy Controller)
- [ ] Block unsigned images in production
- [ ] Log all signature verification attempts
- [ ] Alert on verification failures

### CI/CD Integration
- [ ] Build → Sign → Push → Verify → Deploy
- [ ] Sign images immediately after build
- [ ] Never deploy unverified images
- [ ] Include signature verification in deployment gates
- [ ] Fail builds if signing fails

### Monitoring & Auditing
- [ ] Monitor Rekor transparency log for unexpected signatures
- [ ] Alert on signature verification failures
- [ ] Audit key usage (who signed what, when)
- [ ] Track unsigned image deployment attempts
- [ ] Regularly review admission policy logs

## 🚨 Common Mistakes

### Mistake #1: Signing by Tag Instead of Digest
**Problem:** Tags are mutable; attacker can replace `v1.0` with malicious image  
**Solution:** Always reference images by digest: `myapp@sha256:abc123...`

### Mistake #2: Not Using Admission Control
**Problem:** Developers can still deploy unsigned images manually  
**Solution:** Enforce signature verification with Kubernetes Policy Controller

### Mistake #3: Losing Private Key
**Problem:** Cannot sign new images if key is lost  
**Solution:** Store key in secrets manager with backup, or use keyless signing

### Mistake #4: Signing After Push
**Problem:** Window of opportunity for attacker to pull unsigned image  
**Solution:** Sign immediately after build, before push (or during push)

### Mistake #5: Not Verifying in CI/CD
**Problem:** Signed images bypass verification if CI/CD doesn't check  
**Solution:** Add verification step between pull and deploy

## 🔬 Advanced: SBOM Attestation

**Sign SBOM alongside image:**

```bash
# Generate SBOM
syft packages myapp:v1.0 -o spdx-json > sbom.spdx.json

# Attach SBOM as attestation
cosign attest --key cosign.key --type spdxjson --predicate sbom.spdx.json myapp:v1.0

# Verify SBOM attestation
cosign verify-attestation --key cosign.pub --type spdxjson myapp:v1.0
```

**Why this matters:**

- ✅ Proves SBOM authenticity (not tampered)
- ✅ Binds SBOM to specific image version
- ✅ Enables policy enforcement on dependencies (e.g., "block images with log4j 2.14.0")

## 🎓 Key Takeaways

1. **Image signing prevents supply chain attacks** - Tampered images are detected at deployment

2. **Cosign is the modern standard** - CNCF project, Kubernetes-native, keyless signing support

3. **Sign by digest, not tag** - Tags are mutable, digests are immutable

4. **Admission control is mandatory** - Without enforcement, signing is just audit trail

5. **Key management is critical** - Lose the key = cannot sign new images

6. **Keyless signing simplifies operations** - OIDC-based signing eliminates key storage

7. **SBOM attestations complete the picture** - Sign both image AND bill of materials

8. **Transparency logs provide auditability** - Rekor records all signatures for forensics
